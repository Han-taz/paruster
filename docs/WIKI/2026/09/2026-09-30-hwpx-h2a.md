# HWPX H2a XML and section candidate

## Candidate implementation

The crate-local candidate adds a bounded streaming XML reader, style references,
and section-to-IR lowering. The XML reader uses local element names, rejects
DTD/custom entity declarations, enforces UTF-8, and bounds input (64 MiB), text
(16 MiB), depth (200), node count (100,000), attribute count (100,000), and
estimated tree storage (32 MiB). Resource exhaustion is a hard
`DECOMPRESSION_BOMB`; malformed critical XML is `CORRUPTED`.

Each section is parsed into a temporary delta. It publishes blocks, outline,
and page state only after that section completes successfully. Malformed or
over-depth section XML emits `PARTIAL_PARSE` and preserves sound neighbors;
resource-limit failures escape as hard errors. Section ordering follows a
valid content spine, then numeric section suffix as fallback. The lowering
preserves paragraph/run spans, heading outline, notes, style references, page
evidence, and recursively assigned page numbers. Markdown remains a shared
core projection.

H1a package/security had already merged in PR [#18](https://github.com/Han-taz/paruster/pull/18)
as `e33eab1`; the H2a implementation consumes its private validated package
boundary. No shared public contract or production parser registration is added
by this candidate.

## Evidence and review

At commit `32fe037d1a9609b607cabca929d0da57f1d44145`, the crate has 40 unit
tests across package/XML/sections/styles and 8 integration tests. Tests cover
namespace-local names, DTD/entity refusal, depth behavior, malformed-section
isolation, spine and numeric ordering, spans/headings, footnotes/endnotes,
page-cache handling, and recursive fallback. The eight integration tests
exercise deterministic synthetic recipe construction and structural shapes.

Follow-up review found incomplete-layout selection, note formats with omitted
suffixes, and lost page transitions when empty paragraphs were omitted. Commit
`1c267994eeba25f8e146133cf01cb9b55f277292` added four regression tests and
fixed those cases. The regressions were observed failing before the fixes.
Fresh Hancom tests passed (44 unit, 8 integration); workspace formatting,
strict Clippy, and diff checks passed. Clippy initially encountered the host's
Python 3.9 versus abi3-py310 mismatch, then passed with Python 3.11. Final SOL
review is pending; no hosted result for the candidate is claimed.

The fixture oracle data is candidate research evidence, not a parser parity
claim. Over-depth section behavior intentionally diverges from the oracle's
empty/clipped result in favor of a bounded `PARTIAL_PARSE` warning and is
excluded from parity scoring. There is no production registry integration,
Python HWPX coverage, or successful parser-oracle capture at this checkpoint.
