# PDF Parser Implementation Plan

> **For agentic workers:** Use `superpowers:subagent-driven-development` for the bounded Luna tasks, `superpowers:test-driven-development` for each behavior, and `superpowers:verification-before-completion` before review. This is the P2 child plan of the [product port DAG](2026-09-30-product-port-implementation-plan.md). Checkboxes track work, not parity claims.

**Goal:** Deliver a bounded, pure-Rust PDF semantic parser with layout, tables, images, links, metadata, and quality evidence through the existing Rust core and Python API, with exact full-result oracle parity on representative documents.

**Architecture:** `kordoc-pdf` owns PDF object and content-stream reading, glyph/CMap interpretation, geometric reconstruction, and source-to-IR lowering. It depends on `kordoc-ir` only and returns `ParsedDocument`; coordinator-owned `kordoc-core` performs Markdown/page/chunk projections and public result assembly. PDFium may later supply bounded raster pages to P6 OCR/formula recognition, but it is never needed for the base parse or metadata path. Neither Node nor pdfjs is a product dependency.

**Tech Stack:** Rust 1.97, a bounded pure-Rust `lopdf` substrate if its spike passes, `kordoc-ir`, `kordoc-core`, PyO3 `abi3-py310`, Python 3.10-3.14, Cargo tests/proptest/fuzz, the existing document-result parity harness.

## Deterministic resource and failure contract

Implement one checked `PdfBudget` in `src/limits.rs`; charge *before* allocation, decompression, recursion, object lookup, operator execution, image decode, or IR insertion. Use checked `u64` arithmetic and reject overflow. These are initial maximums for tests and review, not claims that every maximum can be reached simultaneously; cumulative charges prevent that. A limit change needs security and parity review, never a fixture or scoring relaxation.

| Budget | Initial bound and behavior |
| --- | --- |
| Source bytes | Existing core/Python input cap: 524,288,000 bytes; metadata-only path also respects caller's lower MCP cap of 50 MiB. |
| Pages | At most first 5,000 pages parsed; page count remains source count; requested pages beyond the parse cap produce `PARTIAL_PARSE` only where oracle-compatible, otherwise a typed limit failure. Zero pages is invalid. |
| Indirect objects/xref | At most 1,000,000 distinct object IDs and 2,000,000 dereferences per request; reject cycles and invalid generations. |
| Graph/content nesting | At most 64 object-reference levels, 32 Form XObject nesting levels, and 64 graphics-state/marked-content levels. |
| Decoded streams | 32 MiB per stream and 256 MiB cumulative decoded bytes, including object streams and font/CMap/image streams. Predictor and filter output are charged during decode, never afterward. |
| Content work | 500,000 operators per page and 5,000,000 total; 1,000,000 glyph placements per page and 10,000,000 total. Unsupported operators cannot bypass the count. |
| Extracted text and IR | 100 MiB cumulative UTF-8 text; at most 1,000,000 emitted blocks, 2,000,000 table cells, and 256 MiB estimated serialized `ParsedDocument`. Honor P7's tighter recursive/table/projection limits. |
| Geometry and images | Reject nonfinite matrices or page boxes, dimensions outside 1..20,000 PDF points, or checked coordinate overflow. Decode at most 36,000,000 pixels per image, 200 extracted images, and 128 MiB cumulative image bytes; skip optional images with `SKIPPED_IMAGE` only when the source behavior permits. |

Map corrupt xref/stream/required page structures to `CORRUPTED`, encryption/password to the existing `ENCRYPTED` or shared password behavior, scan-only pages to `IMAGE_BASED_PDF` where the frozen result requires failure, and exceeded safety budgets to the existing `OUTPUT_TOO_LARGE` or `DECOMPRESSION_BOMB` code according to the offending resource. Do not mint a new error code or leak passwords, paths, object contents, or native error text. `PARTIAL_PARSE`, `NEEDS_OCR`, and `SKIPPED_IMAGE` are warnings only for recoverable policy cases. Tests assert exact code, omission/null behavior, page number, and warning order.
