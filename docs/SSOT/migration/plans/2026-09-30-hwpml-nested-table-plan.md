# Private HWPML unique-anchor nested tables

> **Status:** Coordinator approved the narrow private H0 unique-anchor slice, typed unsupported rejection for ambiguous attachment/depth 9, and the boundaries below. Implement test-first after the merged shared builder and private text lowerer are present.

**Goal:** Replace hard table rejection for the existing authored H0 nested-table fixture with bounded source-specific lowering that preserves cell geometry, text, nested `IrCell.blocks`, selected-section order, and the trailing-column option.

**Architecture:** `kordoc-hancom::hwpml` interprets HWPML `TABLE`/`ROW`/`CELL`, attributes, captions and paragraph anchors; the merged `kordoc-tables` crate alone handles source-neutral placement/grid construction. Use `build_table_with_blocks`, `TableCellBudget`, and the existing HWPML `LoweringBudget` adapter. No new builder, shared IR mutation, public parser registration, Python/MCP change, or tolerance of malformed XML.

**Tech stack:** Rust 1.97, strict private HWPML XML tree, `kordoc-tables`, frozen H0 CC0 XML/captures and offline contract machinery. The migration oracle is read-only research, absent from Git/runtime/CI/artifacts.

## Resource and security contract

Keep the current inclusive 50 MiB input preflight, strict UTF-8/XML depth/node/text/tree limits, 256 MiB HWPML lowering-allocation budget, page selection, and transactional failure. Define one aggregate `TableCellBudget` for every table in a document, including nested tables, with the shared 2,000,000 logical-cell ceiling; do not instantiate a fresh budget per nested table. Bound both XML traversal depth and nested table/IR block depth before descent. The source's `MAX_TABLE_NEST = 8` is an upper bound for this first slice; choose a stricter fail-closed rejection on depth 9, rather than silently flattening or truncating nested structure. Also honor the shared 64-level IR block limit. Precharge vectors, input cell contexts, flat text, nested blocks, table output and duplicated caption/outline strings before fallible reservation; moving owned payload into the rich builder must not double-count bytes, while transient copies remain charged. Collisions, impossible spans, invalid coordinates, excessive dimensions and allocation failures must produce typed existing errors with no partial document. Any option/skip behavior difference from the oracle is recorded as a private limitation, not hidden by weakening the H0 expectation.

Selected content only: section-level HEADER/FOOTER and unselected sections remain ignored as in the private text slice. A table anchored under a selected `P/TEXT` follows the paragraph in block order; a direct selected-section table occupies its source position. Do not duplicate table text inside the preceding paragraph. Keep paragraph CHAR collection's established suppression of structural `TABLE`, `PICTURE`, `SHAPEOBJECT` and `AUTONUM`; preserve current footnote CHAR behavior. The oracle's table-specific walkers skip TABLE under inline `FOOTNOTE`/`ENDNOTE`/`HEADER`/`FOOTER`; the narrow Rust slice deliberately returns `UNSUPPORTED_FORMAT` when such a TABLE is present in selected paragraph/cell content. This fail-closed divergence prevents an unreviewed table from being emitted or silently lost; ordinary CHAR content without those tables remains unchanged. A declared table with no direct `CELL` is also `UNSUPPORTED_FORMAT` in Rust, whereas the oracle omits that table. Within supported H0 tables, flat cell text and nested block order follow the pinned captures. Captions outside explicitly supported evidence fail closed rather than disappear. Caption placement and partial/recoverable XML behavior require separate evidence; no general claim follows from this first table fixture.
